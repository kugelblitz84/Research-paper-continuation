# Checkpoints and recovery

## Storage contract

Every epoch has a unique directory:

```text
models/checkpoints/<experiment_id>/epoch_001_<generation>/last.pt
models/checkpoints/<experiment_id>/epoch_001_<generation>/best.pt   # if improved
```

`last.pt` contains the complete latest-epoch state. `best.pt` is created only when
validation strictly improves. Both files are immutable and written with exclusive
creation. There is no automatic checkpoint deletion or retention policy.

`experiments/runs/<id>/checkpoints.json` points to the current last and best
checkpoints with SHA-256 values. The pointer is atomically replaced; previous
checkpoint files remain intact. A partially written unreferenced generation after
power loss is never chosen automatically.

At completion, `frozen_checkpoint.json` records the selected best artifact. The
separate evaluator requires this record and completed status. It verifies hashes,
config identity and manifest identity before inference.

Payloads include model/optimizer/scheduler/AMP state, epoch, best score/epoch,
patience counter, architecture/system/seed, exact class mappings, complete config
snapshot and hash, manifest hashes, software environment and resolved weight enum,
history, and Python/NumPy/Torch/CUDA/loader RNG states.

## Resume procedure

1. Ensure the previous process is no longer running and durable artifacts remain.
2. Inspect `run_summary.json` and `checkpoints.json`; check that `last.pt` exists.
3. Reopen the matching training notebook with the same config and environment.
4. Set `RUN_TRAINING=True` and `RESUME=True`; run top-to-bottom.
5. Confirm the first new epoch follows the latest completed saved epoch. Inspect
   the resumed history and registry events, then back up all new generations.

A hard VM termination can leave `active.lock`. It intentionally prevents concurrent
writers. Verify that no training process owns the run, preserve the lock contents
in the run's incident notes, then manually remove only that stale lock. The training
code never assumes a lock is stale or deletes it automatically.

If interruption occurred before the first completed epoch, no resumable checkpoint
exists. Keep that run's incident evidence and start a new explicit experiment ID
through `train(..., experiment_id="<new-id>")`. Update evaluation inputs accordingly.
Completed runs cannot be resumed or overwritten. Config/manifest mismatch blocks
resume. Old incomplete generations remain preserved for inspection.

## Reproducibility limits

The implementation restores main-process RNG and DataLoader generator state.
Single-worker-free synthetic interruption tests match uninterrupted model weights,
history and scheduler state exactly. Historical `persistent_workers=True` means
worker-local augmentation RNG survives epochs but is not captured across VM death.
A resumed multiworker real run therefore cannot claim bit-for-bit equivalence to
an uninterrupted run. This is disclosed rather than changing the historical loader
policy to obtain an artificial exact-resume claim.

## Registry

`experiment_registry.csv` is an append-only event log. A run has a start event and
a terminal event; a resumed run adds more events. The final row for an experiment
ID is its current state. Completed historical rows are never edited. A hard kill
may leave the last event `running` until the explicit resume/incident review.

**Git does not preserve ignored checkpoint files.** Back up checkpoint generations,
run records, evaluation records, predictions, final tables and figures independently
of Git. Only load checkpoints generated by this repository or otherwise explicitly
trusted: resumable PyTorch state uses pickle-compatible objects.
